# XR Collector UI Design Spec

本目錄記錄 XR Collector 的畫面設計：導覽、頁面用途、配色與版型。按鈕操作、進度、錯誤與其他狀態由各功能票開工時，連同功能及驗收計畫一起確認，並更新對應段落。產品需求與分工見 [Round 2 Plan](../round-2-plan.md)；設計稿不代表已交付功能。

XR Collector 是 local-first 的資料收集與搜尋桌面工具。第一版支援 YouTube 影片字幕與頻道訂閱，來源以類型宣告擴充（RSS、網頁等）。

執行環境：Electron desktop app，開發時用瀏覽器連到 Vite dev server 測試。業務邏輯在後端，前端只做呈現與操作觸發。

全 App 設計畫布：https://claude.ai/artifact/JxrwCYd63oDwMqiciaPqzF
（導覽、來源、加入內容、來源詳情、文件、Reader、設定與活動；每個畫面可切換 dark / light）

## 色系

採用 XQLab design system（位於 `~/projects/xqlab/design_system/`）的兩個主題：

- **Dark**：duskblue 暮藍（`:root` 預設）

XR Collector 是文件處理工具，排版比看盤畫面寬鬆，著重閱讀舒適度。

```

│ ┌──────────┐ ┌─────────────────────────────────┐ │
│ │ XR       │ │                                 │ │
│ │ [加入內容]│ │         Main Content            │ │
│ │ ──────── │ │                                 │ │
│ │ 來源     │ │                                 │ │
│ │ 文件     │ │                                 │ │
│ │ 活動  (n)│ │                                 │ │
│ │          │ │                                 │ │
│ │ ──────── │ │                                 │ │
│ │ 設定     │ │                                 │ │
│ │ ● 背景狀態│ │                                 │ │
│ └──────────┘ └─────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- Sidebar 寬度 220px，固定在左側。Reader 模式收合為 64px（僅 icon）。
- 頂部是「加入內容」主要按鈕，任何頁面都可開啟加入內容對話框。
- 導覽項目：來源、文件、活動；設定在底部。活動在有進行中工作時顯示數量徽章。
- 最底部是背景狀態：「背景收集中」「自動收集開啟」或「自動收集已暫停」。
- 沒有獨立的搜尋頁——搜尋整合在文件列表上方。
- 網址：來源 `/`（篩選在 `?type=&q=`）、來源詳情 `/sources/<類型>/<ID>`、文件 `/documents`、Reader `/documents/<ID>`、活動 `/activity`、設定 `/settings`。從 App 內開啟的詳情頁，返回控制回到上一個位置；直接開啟時回到所屬列表。
- 操作結果以右下角短暫提示（toast）顯示。

## 設計決策

### Onboarding（01-onboarding）

#20 的待確認方向：使用者先選目錄，再以單一按鈕顯示「建立知識庫」或「開啟知識庫」。以下雙按鈕描述與 HTML 保留為現有草圖，具體操作及畫面在 #20 開工時一起確認。

提供兩個獨立按鈕：「建立新知識庫」與「開啟既有知識庫」。使用者選擇目錄後，系統檢查目錄內容：

- **空目錄**：「開啟既有知識庫」按鈕淡化（opacity 0.35），引導使用者建立新庫。
- **偵測到既有知識庫**：卡片內出現藍色提示（文件數與訂閱數），兩個按鈕都可用。
- **路徑不可用**（State B）：紅色錯誤提示，顯示失敗路徑，使用者重新選擇目錄。
- **格式無法辨識**（State C）：黃色警告提示，說明可能原因，使用者選擇其他目錄。

路徑、權限與資料格式驗證成功後才進入主畫面；驗證失敗留在設定流程，不默默建立空庫。

### 加入內容

「加入內容」開啟 modal 對話框，只有「貼網址」一個分頁。輸入停止約 500ms 後由服務端辨識網址（`POST /api/url-recognitions`），沒有 scheme 的網址（`youtube.com/watch?v=…`）由服務端補上 https://。一修改輸入就顯示「正在辨識網址…」，先前的辨識卡與操作隨即失效；完成後在輸入框下方顯示辨識卡，對話框底部只有一個主要操作：

- **影片**：「YouTube 影片」與網址，主要操作「收集影片」；送出即建立工作並關閉對話框，不連網預覽標題
- **未訂閱頻道**：頻道名稱與依目前共用設定組成的摘要，例如「訂閱後，先收集最近 1 個月內最新的最多 10 支未收集影片，之後每 30 分鐘自動檢查新內容。所有訂閱共用**自動收集設定**。」，主要操作「訂閱頻道」；自動收集暫停時，摘要說明恢復後才會定時檢查
- **已暫停頻道**：「已暫停」標籤與恢復後補收的範圍，主要操作「恢復訂閱」
- **已訂閱頻道**：「已訂閱」標籤、說明與「查看來源」連結，沒有主要操作
- **無法加入**：黃色卡片說明原因（播放清單、尚未支援的網站、網址不完整、頻道無法解析），沒有主要操作
- **需要登入**：來源類型宣告需要登入時說明要先登入哪個網站

辨識卡的內容、類型文字與操作都來自服務端回傳的 `recognition`，UI 依回傳的 `request` 執行操作，不自行判斷網址種類。

### 來源

來源頁是預設首頁，以表格列出所有訂閱來源。

- **標題列**：「立即檢查」檢查全部啟用中的訂閱；「新增來源」開啟加入內容對話框。
- **收集中提示**：有進行中工作時，表格上方顯示「正在收集 N 項：…（已完成／總數）」與「查看活動」。
- **篩選**：類型 chip（「全部」與每種來源類型，附數量）與名稱篩選框，狀態保存在網址。
- **欄位**：名稱（類型圖示、名稱、類型文字）、文件數、最近新增、狀態，以及列尾操作。點列開啟來源詳情。
- **狀態標籤**：「追蹤中」（綠）、「收集中 N／M」（accent）、「已暫停」（灰）、「錯誤」（紅，最近一次結束的頻道工作失敗）。
- **列尾操作**：啟用中的列顯示暫停圖示；已暫停的列顯示「恢復」按鈕。更多選單提供「查看詳情」「立即檢查」（只檢查這個來源）與「移除」。
- **單篇收集**：沒有篩選時，表格最後一列彙總「不屬於訂閱來源的文件」（單支影片，以及已移除訂閱留下的文件）的篇數與最近新增時間。
- **頁尾**：「上次檢查」「下次檢查」時間；自動收集暫停時顯示「自動收集已暫停」。
- **空狀態**：「還沒有來源」說明與「加入內容」按鈕。

移除來源以確認對話框進行：「停止自動收集，已收集的 N 份文件保留。」與「移除」「取消」。從詳情頁移除後回到開啟詳情前的頁面（例如保留篩選的來源清單）；直接開啟的詳情頁移除後以來源清單取代該筆瀏覽紀錄，上一頁不會回到已移除的來源。

### 來源詳情

來源詳情頁顯示來源名稱、狀態標籤、類型與原始網址，右上角是「暫停」或「恢復」與「移除」。

- **統計卡**：文件數、最近新增、上次檢查、訂閱時間。
- **收集設定**：依共用設定組成的摘要，連結到設定頁的自動收集區塊；所有 YouTube 頻道共用同一組設定。
- **最近收集**：最新 5 份文件，點擊開啟 Reader；「在文件中查看全部」以這個來源篩選文件頁。
- **收集紀錄**：最近 5 次頻道工作，以「首次收集」「恢復補收」「定時檢查」「立即檢查」「接續收集」標示執行原因，附時間與結果（新增 N、沒有新影片、失敗原因）；「全部活動」開啟活動頁。

### 文件與搜尋

文件列表和搜尋合併在同一個畫面。頂部是搜尋欄（含清除按鈕）與單一來源下拉。來源下拉分組列出「全部來源」、每種來源的「全部」項目（目前為「YouTube（全部）」），以及該來源下的各頻道與篇數；不用 chip 排列，頻道多了不會撐爆。選單與篩選使用穩定的來源類型與頻道 ID，不以名稱比對。不在訂閱清單但仍有文件的頻道標示「未訂閱」，沒有頻道 ID 的舊文件歸在「未知頻道」並排在最後。其他來源類型加入時，在選單中新增自己的分組。

每列文件顯示：標題、正文節錄（2 行 clamp，正文開頭的純文字，非 AI 摘要）、來源標籤「YouTube · 頻道」、「發布 YYYY-MM-DD」與較淡的「收集 MM-DD」。沒有發布日期時顯示「發布日期未知」，不以收集日期代替。

- **瀏覽**：沒有查詢字串時依收集時間新到舊排列。列表與來源選單直接讀 Vault，不依賴搜尋引擎。
- **搜尋**：輸入後約 300ms 自動查詢，依關聯性排序，節錄改為命中片段並高亮命中詞，上方顯示「找到 N 份」。較晚送出的查詢一律優先，較早的回應不會覆蓋畫面。
- **分頁**：頁碼分頁，每頁 20 份，顯示總數。
- **狀態**：空 Vault 顯示「加入內容」按鈕並開啟加入內容對話框；搜尋沒有結果時顯示「沒有符合」；搜尋引擎無法使用時顯示警示列與「前往設定」，下方改列 Vault 文件，閱讀不受影響。
- **位置保留**：查詢、來源與頁碼放在網址（`/documents?q=&source=&page=`），捲動位置記在瀏覽紀錄；從 Reader 返回或重新整理都回到相同位置。

**文件刪除**（刪除功能交付後加入列與 Reader 的刪除圖示）：確認後刪除文件，Vault 保存刪除／略過記錄；後續排程與手動頻道批次抓取均略過。使用者明確以單支 URL 重新收集且保存成功後，才解除略過狀態；刪除文件不移除訂閱。

### 文件閱讀

Reader 的網址是 `/documents/<文件 ID>`，可重新整理或直接開啟；找不到文件時顯示「找不到這份文件」與返回按鈕。Sidebar 收合為 64px icon-only 模式，把最大空間留給閱讀區域；窄視窗時 Sidebar 回到頂部導覽。

閱讀排版參數：

- 內容寬度 720px，水平置中
- 正文字級 16px
- 行高 1.8
- 正文色 `textBody`（比 `textPrimary` 柔和，適合長文閱讀）

頂部工具列有返回按鈕與「開啟原始影片」：從來源詳情開啟時返回按鈕寫「來源」並回到詳情，其他情況寫「文件」；刪除文件按鈕在刪除功能交付前停用。來源名稱在對應的訂閱仍存在時連結到來源詳情。Metadata 顯示來源標籤、標題（28px）、發布與收集日期、字幕語言與人工／自動字幕，以及原始網址；原始網址在系統瀏覽器開啟。正文以 Markdown 排版（標題、清單、強調、連結、表格），正文中的 HTML 以文字顯示，外部連結在系統瀏覽器開啟，遠端圖片不載入、改為連結。Reader 不標示搜尋命中。

### 設定

內容區域限制在 720px 寬，以區塊分段。已交付的區塊是知識庫（路徑與文件數）、自動收集、搜尋與外觀；其餘區塊隨各自的功能票加入。完整設計分成 7 個區塊：

1. **知識庫 (Vault)**：顯示目前路徑、搬移按鈕
2. **匯出與匯入**：匯出 Vault、合併至目前知識庫、還原為另一份知識庫（匯入拆成兩個獨立操作）
3. **自動收集**：所有訂閱共用的 Global 設定，每次修改立即儲存並在標題旁短暫顯示「已儲存」。
   - 總開關：開啟時顯示「定時檢查已開啟」；關閉時顯示「自動收集已暫停」並說明新訂閱的首次收集與「立即檢查」照常執行。還原產生的 Vault 預設關閉，在這裡恢復
   - 檢查頻率下拉：15 分、30 分、1 小時、3 小時、6 小時、12 小時、每天（預設 30 分）
   - 補收範圍：「最近 [1 週／2 週／1 個月／3 個月／6 個月] 內最新的最多 [5／10／20／50 則]」（預設 1 個月、10 則）
   - 說明：所有訂閱共用；補收範圍用於首次收集、恢復訂閱，以及服務重新啟動或長時間沒有檢查之後，修改後不重新回溯既有頻道；持續運作時每次檢查收完上次之後的新內容
   - 下次與上次檢查時間
4. **搜尋**：狀態指示燈（就緒／啟動中／更新中／重建中／無法使用）、「已索引 N 份／知識庫 M 份」、上次重建時間、無法使用時的原因，以及「重建索引」按鈕；篇數不同時提示可重建
5. **啟動與常駐**：「登入電腦後自動啟動」toggle（預設關閉），說明啟用後背景啟動不開主視窗
6. **外觀**：深色/淺色主題切換
7. **關於與更新**：版本號、檢查更新按鈕、更新狀態（已是最新版 / 有新版 / 失敗）

### 活動記錄（06-activity）

活動頁列出收集工作：執行原因、來源、進度、結果與失敗原因。wireframe 的完整設計在上方顯示工作摘要與進度，下方為 Raw log viewer，等寬字體（`ui-monospace`），表格式三欄結構：

| 欄位 | 寬度 | 說明 |
|---|---|---|
| 時間 | 140px | `MM-DD HH:mm:ss` 格式 |
| 等級 | 60px | 色彩編碼的 level tag |
| 訊息 | flex | 操作描述 |

等級色彩：

- `INFO`：accent 藍（一般資訊）
- `OK`：statusGreen（成功新增）
- `DONE`：statusGreen（批次完成）
- `SKIP`：textTertiary 灰（已略過）
- `ERR`：statusError 紅（失敗）

提供時間、等級與工作篩選，以及載入更多；來源操作可直接跳到該工作的記錄。表頭 sticky，背景色與 log 區域一致。

後端寫 persistent log files，此畫面讀取並顯示。Agent API 也可以讀取 log 供使用者透過 Agent 查問題；Agent 可操作完整業務 API。活動記錄預設保留 30 天，工作接續資料另行保存。

### 桌面常駐與更新

關閉主視窗後隱藏至 Windows 系統匣／macOS 選單列，背景服務繼續收集；常駐入口顯示進度，提供開啟視窗、活動記錄及明確退出。登入自動啟動預設關閉，啟用後背景啟動、不開主視窗。

設定頁及常駐入口均提供手動檢查更新。自動檢查發現新版先通知；使用者明確觸發更新後才下載、安裝與重啟。

## 尺度

- 圓角：6px（輸入框、按鈕）、8px（卡片、面板）
- 間距：沿用 XQLab design system 的 `--p-*` 級距，但整體比看盤畫面寬鬆
- 頁面標題：22px, font-weight 600
- 卡片標題：14–16px, font-weight 500–600
- 正文：14px（列表）、16px（閱讀）
- 次要文字：12–13px
