# XR Collector UI Design Spec

本目錄記錄 XR Collector 的畫面設計：導覽、頁面用途、配色與版型。按鈕操作、進度、錯誤與其他狀態由各功能票開工時，連同功能及驗收計畫一起確認，並更新對應段落。產品需求與分工見 [Round 2 Plan](../round-2-plan.md)；設計稿不代表已交付功能。

XR Collector 是 local-first 的資料收集與搜尋桌面工具。第一版支援 YouTube 影片字幕與頻道訂閱，其他類型以類型宣告擴充（RSS、網頁等）。

執行環境：Electron desktop app，開發時用瀏覽器連到 Vite dev server 測試。業務邏輯在後端，前端只做呈現與操作觸發。

全 App 設計畫布：https://claude.ai/artifact/JxrwCYd63oDwMqiciaPqzF
（導覽、訂閱、新增選單與對話框、訂閱詳情、文件、Reader、工作、設定與記錄；每個畫面可切換 dark / light）

## 色系

採用 XQLab design system（位於 `~/projects/xqlab/design_system/`）的兩個主題：

- **Dark**：duskblue 暮藍（`:root` 預設）

- Sidebar 寬度 220px，固定在左側。Reader 模式收合為 64px（僅 icon）。
- 導覽項目：訂閱、文件、工作、記錄；設定在底部。側欄沒有新增按鈕，新增從各頁頁首開始。
- 「工作」旁的數字是進行中加排隊中的工作數，不含失敗；沒有未結束的工作時不顯示。
- 沒有獨立的搜尋頁——搜尋整合在文件列表上方。
- 網址：訂閱 `/`（篩選在 `?type=&q=`）、訂閱詳情 `/sources/<類型>/<ID>`、文件 `/documents`、Reader `/documents/<ID>`、工作 `/jobs`、記錄 `/activity`、設定 `/settings`。從 App 內開啟的詳情頁，返回控制回到上一個位置；直接開啟時回到所屬列表。
- 操作結果以右下角短暫提示（toast）顯示；新增送出後不顯示提示。

## 用語

| 詞 | 意思 | 用在 |
|---|---|---|
| 訂閱 | 持續關注、會自動更新的對象 | 側欄頁名、新增訂閱、訂閱詳情、移除訂閱 |
| 檢查 | 查看訂閱有沒有新內容 | 自動檢查（全域開關）、立即檢查、檢查頻率、上次檢查、下次檢查 |
| 收集 | 把一則內容抓成一份文件 | 收集紀錄、收集設定 |

各平台的東西沿用平台原名：YouTube 頻道、X 帳號、Facebook 粉專、RSS。畫面、錯誤訊息與 Agent Skill 都用這組詞；API 欄位名稱與路由不變。

## 設計決策

### Onboarding（01-onboarding）

#20 的待確認方向：使用者先選目錄，再以單一按鈕顯示「建立知識庫」或「開啟知識庫」。以下雙按鈕描述與 HTML 保留為現有草圖，具體操作及畫面在 #20 開工時一起確認。

提供兩個獨立按鈕：「建立新知識庫」與「開啟既有知識庫」。使用者選擇目錄後，系統檢查目錄內容：

- **空目錄**：「開啟既有知識庫」按鈕淡化（opacity 0.35），引導使用者建立新庫。
- **偵測到既有知識庫**：卡片內出現藍色提示（文件數與訂閱數），兩個按鈕都可用。
- **路徑不可用**（State B）：紅色錯誤提示，顯示失敗路徑，使用者重新選擇目錄。
- **格式無法辨識**（State C）：黃色警告提示，說明可能原因，使用者選擇其他目錄。

路徑、權限與資料格式驗證成功後才進入主畫面；驗證失敗留在設定流程，不默默建立空庫。

### 新增

文件頁頁首「新增」與訂閱頁頁首「新增訂閱」各有一份選單，開在按鈕下方，不分組：

| 頁面 | 按鈕 | 項目 | 結果 |
|---|---|---|---|
| 文件 | 新增 | 網址、檔案、寫筆記 | 一份文件，之後不再更新 |
| 訂閱 | 新增訂閱 | YouTube 頻道、X 帳號、Facebook 粉專、RSS | 一個訂閱，定期收進新文件 |

選單是 `role=menu`：方向鍵在項目間移動，Esc 或點選單外關閉，關閉後焦點回到按鈕。尚未實作的項目右側標灰色「尚未支援」，點下開啟小對話框：標題是該項目的對話框標題，內文「目前還不支援＿＿。」，按鈕「知道了」。兩頁的空狀態按鈕開啟各自的選單。

可用項目開啟該類型的對話框，標題就是項目（「加入網址」「訂閱 YouTube 頻道」），使用一般對話框的標題列（左側標題、右側關閉），沒有分頁，開啟時焦點在網址欄位。輸入停止約 500ms 後由服務端辨識網址（`POST /api/url-recognitions`），沒有 scheme 的網址由服務端補上 https://。一修改輸入就顯示「正在辨識網址…」，先前的辨識卡與操作隨即失效：

- **類型不符**：「加入網址」貼上頻道網址顯示「這是 YouTube 頻道，要改為訂閱嗎？」與「改為訂閱」；「訂閱 YouTube 頻道」貼上影片網址顯示「這是單支影片，要改為加入一次嗎？」與「改為加入一次」。主要按鈕停用，切換後網址保留並重新辨識。只依辨識的種類判斷，YouTube 冷卻中無法預覽的頻道同樣提示。
- **不支援的網址**：「加入網址」貼上 YouTube 以外的網址顯示「目前還不支援這個網址。」，主要按鈕停用。
- **影片**：「YouTube 影片」與網址，主要操作「加入」；不連網預覽標題。
- **未訂閱頻道**：頻道名稱、這個訂閱的收集設定與摘要，主要操作「訂閱」。設定是「檢查頻率」下拉與「每次檢查　收集最近 [時間範圍] 內最新的 [數量]」，從類型的預設值開始；摘要隨設定更新。自動檢查關閉時，摘要說明開啟後才會定時檢查。
- **已暫停頻道**：「已暫停」標籤與恢復後每次檢查的收集範圍，主要操作「恢復訂閱」。
- **已訂閱頻道**：「已訂閱」標籤與「查看訂閱」連結，主要操作停用。
- **無法加入**：黃色卡片說明原因（播放清單、網址不完整、頻道無法解析）。

送出後對話框關閉，留在原本的頁面，不跳頁、不跳提示。文件頁不列進行中的單次加入，進行中與失敗的工作在工作頁查看。

### 訂閱

訂閱頁是預設首頁，以表格列出所有訂閱，不列單次加入的文件。

- **標題列**：「自動檢查」開關控制所有訂閱的定時檢查，關閉時新訂閱的首次收集與「立即檢查」照常執行；「立即檢查」檢查全部啟用中的訂閱；「新增訂閱」開啟選單。
- **篩選**：類型 chip（「全部」與每種類型，附數量）與名稱篩選框，狀態保存在網址。
- **欄位**：名稱（類型圖示、名稱、類型文字）、文件數、最近新增、狀態，以及列尾操作。點列開啟訂閱詳情。
- **狀態欄**：服務計算（`checkStatus`），只放短文字。檢查開始後不回到排隊中；頻道內某一則最終失敗不改變狀態。
  - 「排隊中」（灰）：檢查還沒開始、等輪到，包括已到期尚未派工。
  - 「檢查中」（accent）：正在列出項目、還不知道總數；沒有新項目的檢查從「檢查中」直接到「下次 HH:MM」。
  - 「下載中 3/10」（accent）：檢查知道要收幾則之後。擷取輪到其他工作時維持「下載中 k/n」，k 停在當時的數字。
  - 「錯誤・14:02 重試」（黃）：會自動重試、目前無法前進：頻道自己的步驟在等重試或 YouTube 冷卻，或還沒收的每一則都在等。還有任何一則在擷取時維持「下載中 k/n」。原因在訂閱詳情。
  - 「新增中」（accent）：訂閱請求正在解析網址。
  - 「下次 18:52」「下次 明天 08:00」「下次 10-24 08:00」（綠）、「已暫停」「自動檢查已關閉」（灰）、「需要重新登入」（紅）。上次檢查失敗仍顯示下次時間，原因在記錄頁與訂閱詳情。
- **新增中的訂閱**：送出後立即出現一列，解析出頻道後換成該訂閱；解析失敗時該列消失並顯示錯誤提示。
- **列尾操作**：啟用中的列顯示暫停圖示；已暫停的列顯示「恢復」按鈕。更多選單提供「查看詳情」「立即檢查」（只檢查這個訂閱）與「移除」。
- **頁尾**：「上次檢查 時間（名稱）· 下次檢查 時間（名稱）」；自動檢查關閉時後半改為「自動檢查已關閉」。
- **空狀態**：「還沒有訂閱」與「新增訂閱」選單按鈕。

移除訂閱以確認對話框進行；頻道有文件或還有收集在進行時，有兩個選項：「保留 N 份文件」（預設）與「一併刪除 N 份文件」。一併刪除的文件留下刪除紀錄，與一般刪除相同；有文件刪不掉時，提示寫明幾份無法刪除。從詳情頁移除後回到開啟詳情前的頁面；直接開啟的詳情頁移除後以訂閱清單取代該筆瀏覽紀錄。

### 訂閱詳情

訂閱詳情頁顯示名稱、狀態欄文字、類型與原始網址，右上角是「暫停」或「恢復」與「移除」。

- **最近一次檢查失敗**：最近結束的頻道工作列出頻道失敗時，標題下方顯示原因；影片失敗不算。
- **統計卡**：文件數、最近新增、上次檢查、新增時間。
- **收集設定**：這個訂閱的「檢查頻率」與「每次檢查　收集最近 [時間範圍] 內最新的 [數量]」，修改後立即儲存，標題旁短暫顯示「已儲存」；下方一行「下次檢查」顯示時間，已暫停或自動檢查關閉時說明原因。標題列的「套用到所有 YouTube 頻道」先開確認對話框，說明會套用到其他幾個頻道（含幾個已暫停）；確認後套用，已暫停的頻道保持暫停。
- **收集紀錄**：一個列表，新到舊，最多 30 筆，沒有重試按鈕。每支影片一筆，顯示目前狀態：
  - 收集到的影片：點擊開啟 Reader；
  - 失敗的影片：原因與已試次數，例如「沒有字幕・已試 2/3 次」；
  - 已略過的影片：「已略過・已試 3 次」或「已略過・影片不存在」。

  每次結束的檢查一筆摘要，例如「定時檢查・收集 2 支」「定時檢查・沒有新影片」「立即檢查・收集 1 支・失敗 1 支」，以「首次收集」「恢復後檢查」「定時檢查」「立即檢查」標示執行原因。

**與設計畫布的差異**：

- 「套用到所有 YouTube 頻道」會覆寫其他所有頻道（含已暫停）的設定且無法復原，所以先以確認對話框說明影響的數量。
- 各訂閱的檢查時間不同，「下次檢查」放在訂閱詳情的收集設定下方；訂閱頁頁尾的上次與下次檢查附上訂閱名稱。

### 文件與搜尋

文件列表和搜尋合併在同一個畫面。頂部是搜尋欄（含清除按鈕）、單一頻道下拉，標題列右側是「新增」選單。頻道下拉分組列出「全部（n）」、每種類型的「全部」項目（目前為「YouTube・全部（n）」），以及該類型下的各頻道與篇數；不用 chip 排列，頻道多了不會撐爆。選單與篩選使用穩定的類型與頻道 ID，不以名稱比對。已移除訂閱留下文件的頻道顯示「名稱・已移除（n）」，名稱取自移除紀錄；只單次加入過的頻道不標示；沒有頻道 ID 的舊文件歸在「未知頻道」並排在最後。其他類型加入時，在選單中新增自己的分組。

每列文件顯示：標題、正文節錄（2 行 clamp，正文開頭的純文字，非 AI 摘要）、標籤「YouTube · 頻道」、「發布 YYYY-MM-DD」與較淡的「收集 MM-DD」。沒有發布日期時顯示「發布日期未知」，不以收集日期代替。

- **瀏覽**：沒有查詢字串時依收集時間新到舊排列。列表與頻道選單直接讀 Vault，不依賴搜尋引擎。
- **搜尋**：輸入後約 300ms 自動查詢，依關聯性排序，節錄改為命中片段並高亮命中詞，上方顯示「找到 N 份」。較晚送出的查詢一律優先，較早的回應不會覆蓋畫面。
- **分頁**：頁碼分頁，每頁 20 份，顯示總數。
- **狀態**：空 Vault 顯示「新增」選單按鈕；搜尋沒有結果時顯示「沒有符合」；搜尋引擎無法使用時顯示警示列與「前往設定」，下方改列 Vault 文件，閱讀不受影響。
- **位置保留**：查詢、頻道與頁碼放在網址（`/documents?q=&source=&page=`），捲動位置記在瀏覽紀錄；從 Reader 返回或重新整理都回到相同位置。

**文件刪除**（刪除功能交付後加入列與 Reader 的刪除圖示）：確認後刪除文件，Vault 保存刪除／略過記錄；後續排程與手動頻道批次抓取均略過。使用者明確以單支 URL 重新收集且保存成功後，才解除略過狀態；刪除文件不移除訂閱。

### 文件閱讀

Reader 的網址是 `/documents/<文件 ID>`，可重新整理或直接開啟；找不到文件時顯示「找不到這份文件」與返回按鈕。Sidebar 收合為 64px icon-only 模式，把最大空間留給閱讀區域；窄視窗時 Sidebar 回到頂部導覽。

閱讀排版參數：

- 內容寬度 720px，水平置中
- 正文字級 16px
- 行高 1.8
- 正文色 `textBody`（比 `textPrimary` 柔和，適合長文閱讀）

頂部工具列有返回按鈕與「開啟原始影片」：從訂閱詳情開啟時返回按鈕寫「訂閱」並回到詳情，其他情況寫「文件」。頻道名稱在對應的訂閱仍存在時連結到訂閱詳情。Metadata 顯示類型標籤、標題（28px）、發布與收集日期、字幕語言與人工／自動字幕，以及原始網址；原始網址在系統瀏覽器開啟。正文以 Markdown 排版（標題、清單、強調、連結、表格），正文中的 HTML 以文字顯示，外部連結在系統瀏覽器開啟，遠端圖片不載入、改為連結。Reader 不標示搜尋命中。

### 設定

內容區域限制在 720px 寬，以區塊分段。已交付的區塊是知識庫（路徑與文件數）、搜尋與外觀；其餘區塊隨各自的功能票加入。完整設計分成 6 個區塊；自動檢查開關在訂閱頁，收集設定在各訂閱詳情：

1. **知識庫 (Vault)**：顯示目前路徑、搬移按鈕
2. **匯出與匯入**：匯出 Vault、合併至目前知識庫、還原為另一份知識庫（匯入拆成兩個獨立操作）
3. **搜尋**：狀態指示燈（就緒／啟動中／更新中／重建中／無法使用）、「已索引 N 份／知識庫 M 份」、上次重建時間、無法使用時的原因，以及「重建索引」按鈕；篇數不同時提示可重建
4. **啟動與常駐**：「登入電腦後自動啟動」toggle（預設關閉），說明啟用後背景啟動不開主視窗
5. **外觀**：主題切換：跟隨系統、深色、淺色（預設跟隨系統）
6. **關於與更新**：版本號、檢查更新按鈕、更新狀態（已是最新版 / 有新版 / 失敗）

### 工作

工作頁只列整筆工作：單支影片，或一個頻道的一次檢查；頻道內的各則不單獨列出。工作不論來自 UI 或 Agent，分三段，各段標題旁有筆數：

- **進行中**：已開始、尚未結束的工作。每列右側是狀態：檢查為「檢查中」或「下載中 3/10」並附進度條，單支影片為「下載中」，新增訂閱為「新增中」。會自動重試、目前無法前進的工作顯示「錯誤・10:35 重試」（黃），列下方以黃字寫原因與次數，例如「網路錯誤（第 2／3 次）」「YouTube 限制連線」。工作開始後一直留在這一段，直到結束。
- **排隊中**：還沒開始的工作，附順序編號，依輪到的順序；YouTube 冷卻期間還沒開始的工作也在這裡。
- **失敗**：失敗的單支影片與新增訂閱，顯示原因，附「重試」與「移除」。重試成功、移除、同一支影片已有文件或失敗滿 7 天後離開；之後仍可在記錄頁查到。頻道內失敗的影片不列在這裡，只出現在訂閱詳情。

每一列的圖示代表來源類型，與訂閱頁相同；檢查、新增訂閱與單篇以副標區分：檢查是「頻道・檢查」，新增訂閱是「頻道・新增訂閱」（「頻道」由來源類型決定），單篇是發布者名稱；還沒有標題的項目顯示網址。不列已完成的工作與排定的下一次檢查，也沒有取消按鈕。三段都沒有內容時顯示「沒有進行中的工作」。

### 記錄（06-activity）

記錄頁只列記錄，屬於某個來源類型的記錄在等級後附該類型的小圖示，系統記錄不附。wireframe 為 Raw log viewer，等寬字體（`ui-monospace`），表格式三欄結構：

| 欄位 | 寬度 | 說明 |
|---|---|---|
| 時間 | 140px | `MM-DD HH:mm:ss` 格式 |
| 等級 | 60px | 色彩編碼的 level tag |
| 訊息 | flex | 操作描述 |

等級色彩：

- `INFO`：accent 藍（一般資訊）
- `OK`：statusGreen（成功新增）
- `DONE`：statusGreen（批次完成）
- `SKIP`：textTertiary 灰（已略過）
- `ERR`：statusError 紅（失敗）

提供時間、等級與訂閱篩選，以及載入更多；網址帶工作 ID 時只列該工作的記錄。表頭 sticky，背景色與 log 區域一致。

後端寫 persistent log files，此畫面讀取並顯示。Agent API 也可以讀取 log 供使用者透過 Agent 查問題；Agent 可操作完整業務 API。記錄預設保留 30 天，工作接續資料另行保存。

### 桌面常駐與更新

關閉主視窗後隱藏至 Windows 系統匣／macOS 選單列，背景服務繼續收集；常駐入口顯示進度，提供開啟視窗、記錄及明確退出。登入自動啟動預設關閉，啟用後背景啟動、不開主視窗。

設定頁及常駐入口均提供手動檢查更新。自動檢查發現新版先通知；使用者明確觸發更新後才下載、安裝與重啟。

## 尺度

- 圓角：6px（輸入框、按鈕）、8px（卡片、面板）
- 間距：沿用 XQLab design system 的 `--p-*` 級距，但整體比看盤畫面寬鬆
- 頁面標題：22px, font-weight 600
- 卡片標題：14–16px, font-weight 500–600
- 正文：14px（列表）、16px（閱讀）
- 次要文字：12–13px
