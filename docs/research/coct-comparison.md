# COCT 與預設中文斷詞的受控比較

日期：2026-10-27。使用者指定先比較國教院 COCT 與 barebone；McBopomofo 留作後續候選。本次是隔離實驗，不替換產品引擎、不改 #162 正規化、不更新使用者索引。原始詞頻資料與衍生詞檔只留本機 gitignored artifacts，沒有隨本文件提交。

## 結論

COCT作為帶頻率Jieba主詞庫的方向成立：在此小型真實資料集排除已知分散字誤命中、保留全部原有已標註命中，沒有全量dictionary API的明顯延遲。這是Mac arm64隔離引擎比較，不是正式產品整合或完整搜尋品質證明。McBopomofo本輪未比較，沒有據此判定COCT勝過它。

接入方式很重要：不應把16萬詞無頻率地整包塞入dictionary API。這條路已觀察到跨詞界誤切、真實正例消失及約半秒查詢成本。

## 實驗定義

Barebone 指目前 Meilisearch 1.53.2 中文 runtime 的預設 Jieba 詞庫與 Charabia 切分。兩邊文件及查詢皆使用相同 #162 正規化，避免把繁簡轉換的效益混入詞庫比較。

資料是 [COCT 官方通用詞頻表，定稿1141208.xlsx](https://coct.naer.edu.tw/file/files/%E9%80%9A%E7%94%A8%E8%A9%9E%E9%A0%BB%E8%A1%A8%20-%20%E5%AE%9A%E7%A8%BF1141208.xlsx)，SHA256 `bfd3b73938e115ae39a44c5e11c97135c09939cf598157cb2fe0b33c4302de75`。2025-12-08 是發布檔案時間，不代表語料蒐集年份。下載頁未找到這份資料明確的產品散布授權；此狀態保留，不將「公開下載」推論成「已有開放授權」。

原始163701詞，經產品 normalizeSearchText 處理後有162966不同詞形；730組詞形碰撞，沒有空白／空詞拒收。沒有人工補入失敗詞，也沒有公司別名或地區用詞替換。

接入分成兩條，不能把結果互相替代：

1. **帶頻率主詞庫 probe**：jieba-rs 0.10.3 從空庫載入 COCT，使用新聞 raw count；正規化碰撞詞加總，零次數439詞固定取1。這是首輪明確固定的權重方案，尚未比較其他語域或平滑方法。保留 Charabia 0.10.0 原始二次切分，另作關閉二次切分的交叉對照。測74個不同正規化文本，含既有查詢與正反例。
2. **真實 Meilisearch 搜尋**：先將COCT詞頭全量傳給dictionary setting，無頻率；再編譯帶詞頻COCT主詞庫的隔離Meilisearch，dictionary setting明確保持空白。34文件／60查詢沿用凍結資料，正反例另置索引，避免污染真實文件比較。設定與非同步任務均等到成功後讀回核對。

## 主詞庫與二次切分結果

表格為最終 Charabia words；兩組 barebone 在這五詞上關閉二次切分仍相同。

| 詞 | Barebone | COCT＋原始二次切分 | COCT＋關閉二次切分 |
| --- | --- | --- | --- |
| 觀光 | 觀／光 | 觀光 | 觀光 |
| 資安 | 資／安 | 資安 | 資安 |
| 拆股 | 拆／股 | 拆／股 | 拆／股 |
| 半導體 | 半／導／體 | 半導體 | 半導體 |
| 台積電 | 台／積／電 | 台積／電 | 台積電 |

COCT確實修復常用繁體詞覆蓋。「台積電」第一輪Jieba已完整，但二次切分優先取已知二字詞「台積」，於是拆為台積／電。這是可獨立重現的第二個原因，並非詞庫缺少台積電，也不是繁簡轉換把它拆開。

其他觀察：

- 「直觀地看，期權賣光了」在COCT下是直觀／地／看／期權／賣光／了；原始預設把直觀、期權拆字。此詞界改善是否消除假命中，需看下一節真引擎，不能只從tokens宣稱搜尋已修好。
- 「拆股」不在COCT，仍拆字，不能宣稱一次換庫覆蓋全部財經詞。
- 「伺服器」兩種主庫都能第一輪完整切出，但原始二次切分皆成伺服／器。
- 「人工智慧」在預設Jieba第一輪完整，但COCT第一輪為人工／智慧；原始二次切分下兩邊最終皆人工／智慧。不同詞庫有詞界標準差異，詞數多寡不是品質指標。
- 74文本中有34個最終token序列改變。這是變動數，不是34題改善，也不是準確率。

上述四組程式耗時包含啟動、詞庫初始化及檔案cache差異，不作搜尋效能比較。關閉二次切分只用來釐清因果，尚未宣稱為可交付策略。

## 帶詞頻主庫的完整引擎比較

另編譯Meilisearch 1.53.2 Mac arm64 release，維持原Chinese features、Charabia 0.10.0與jieba-rs 0.10.3；唯一原始碼差異為Charabia的靜態Jieba改從內嵌COCT詞頻檔載入，原始二次切分保留。實驗二進位SHA256 `bfd2e5a693b8044702afb2f59bc52d1172848801cd80e7858f9c2baa59877163`。產品resources/bin、共享上游source及Cargo registry均未修改。

兩個binary各用同一single-engine runner、空dictionary、相同34文件／60查詢及180次暖查詢，使用不同新DB。這組公平對照獨立於下一節交替查詢的API實驗。

| 真實查詢 | Barebone命中數 | COCT主庫命中數 | 核對 |
| --- | ---: | ---: | --- |
| 觀光 | 6 | 1 | 原標註正例保留；已知QQQI分散字誤命中消失 |
| 資安 | 10 | 2 | 原標註正例保留 |
| 拆股 | 2 | 1 | 原標註正例保留；COCT仍未收拆股，改善來自周邊詞界 |
| 台越 觀光 | 3 | 1 | 原標註正例保留 |
| 風電 | 5 | 1 | 原能源新聞正例保留，沒有API全量組的失召回 |
| 台積電 | 1 | 1 | 原標註正例保留；token仍為台積／電 |

60題有14題命中或排序變動。預先標註的50組query-document正例，兩邊皆命中49組；唯一漏查是既有M30「台績電」未找出台積電。五題預期零命中的查詢沒有違反。原真實題庫沒有預先指定forbiddenIds，故不把空的forbidden結果當完整precision證明。

另置10文件（五正例、五負例）測觀光、資安、半導體、台積電、拆股；各做quoted與unquoted共10次查詢，COCT全部保留對應正例、排除對應分散字負例。這只證明這些已指定案例，不代表所有中文歧義都解決。

| 同流程180次暖查詢 | Barebone | COCT主庫 |
| --- | ---: | ---: |
| HTTP p50 | 6.18ms | 3.04ms |
| HTTP p95 | 40.88ms | 39.60ms |
| 單次34文件索引建置（含初始化） | 2.39s | 1.85s |

本次沒有觀察到主庫接法的延遲退步；單機、小資料、單次索引及不同程序時序不足以宣稱普遍加速。正式整合前仍需更多台灣文本與獨立保留題，並明訂部分詞查詢行為。

**主庫接法仍有未解的短片段問題，並非API獨有：**

- 「半導」真實文件6→7，fixture1→2，新增「半」年過後「導」師安排體驗活動的分散字負例。完整詞「半導體」的正反例通過，不代表短片段「半導」也通過。
- 「導體」真實文件9→0，fixture2→0，「半導體製程進步」也不再命中。若產品要支援詞內片段，這就是需要另外處理的取捨。
- 真實文件中的「台積」2→1、「觀」8→3、「資」13→11；「電」13→13。這些題沒有完整相關性標註，不用數量下降宣稱改善，亦不承諾原有單字召回不變。
- 「股」11→11仍交換了兩篇真實RSS：新增含「每股120元」的亞昕新聞、移除含「個股」的穩懋新聞；「金」不再命中含「自由現金流量」的字幕。這些是實際字面包含但未列入原expectedIds的召回變動，因此不能把「既定50組正例無新增漏查」擴張成「所有字面相關文件都無新增漏查」。
- 「半導」新增fixture負例不只進入結果，還排在半導體正例前；這是已觀察到的誤命中及排序退步，不能以完整詞案例通過帶過。

因此本輪支持的是「COCT作通用繁體主庫可改善完整詞」，尚未解決未登錄短詞、詞內片段與分散字匹配的整體規則；也不能僅憑本次probe就把二次切分全部關掉。

## 全量 dictionary API 的搜尋結果

以162966詞作無頻率dictionary setting，原34文件／60查詢中有15題命中或排序改變。部分短詞的誤命中大幅減少：觀光6→1、資安10→2、台越觀光3→1。但「風電」5→0，遺失人工標註應命中的真實能源新聞；既有「台績電」錯字漏查仍未修復。命中變少本身不是品質指標，需逐題核對。

暖查詢每組180次（60題×3輪），HTTP端到端p50由6.91ms升為473.01ms，p95由43.25ms升為515.90ms。這是同機小資料實測，沒有跨機或大量文件效能保證。COCT資料成功載入不代表全量dictionary API是合適接入方式。

風電失召回已由實際索引匹配位置及獨立Charabia words_dict probe共同確認：

| 接法 | 真實標題中的「離岸風電」 |
| --- | --- |
| Barebone | 離／岸／風／電 |
| COCT dictionary API／words_dict | 離岸風／電 |
| COCT帶詞頻Jieba主庫，保留原二次切分 | 離岸／風電 |

COCT同時含離岸、離岸風、風電；無頻率的最左最長匹配先消耗離岸風，造成跨詞界衝突。帶頻率的Jieba路徑選擇則保留風電。這是兩種接法的行為差異，不能據此判定COCT詞庫本身較差。

另外以COCT的五詞（觀光、資安、半導體、台積電、伺服器）作小字典對照，觀光6→1、資安10→2、台越觀光3→1，且風電原有召回保留。「拆股」依然2筆；全量字典中拆股2→1是周邊詞界改變的副作用，不能說COCT新增了拆股。

小字典短批次各5題median為barebone31.98ms、全量483.18ms、小字典3.09ms；這個樣本很小，題目分布也不同於前述180次，只用來辨認全量接入成本，不能說小字典比barebone快十倍。

部分詞另有取捨：全量字典下「導體」在34真實文件命中9→0，在獨立fixture則2→0，包含「半導體製程進步」也不再命中；「半導」新增一筆包含「半年過後導師安排體驗活動」的負例。小字典在真實文件中亦改變「導體」9→7、「電」13→12。這些探索題沒有完整相關性標註，命中數變動本身不判作改善或退步，但需要釐清期望的部分詞查詢行為。鎖定整詞沒有自動解決所有部分詞／歧義查詢。

## 本機重現與證據

證據位於本票 `.local/ticket-artifacts/162/coct-comparison/`：來源checksum、完整欄位與版本在source.json；轉換規則與碰撞在preparation.json；詞庫在coct-news.txt／coct-terms.json；四組結果在tokenizer-results.json與對應TSV。prepare.mts直接使用產品正規化函式，run-tokenizers.py重跑四組。

完整引擎資料在matched-barebone-engine及coct-main-engine各自的results.json／extra-results.json；建置來源、flags、hash與最小diff在engine/build-manifest.json及engine/charabia.patch。API實驗與短字典對照保留在run-2，兩條接法不混算。

Rust probe位於 `.local/ticket-artifacts/162/tokenizer-root-cause/`，固定charabia 0.10.0、jieba-rs 0.10.3。只有此隔離副本增加環境變數選擇詞庫與跳過二次切分；產品Cargo／runtime未變。

這是研究用比較，並非 #162 整體驗收重跑。沒有改產品程式或正式測試，因此沒有為本輪重新執行 npm run verify；先前 #162 的驗證結果也不拿來代替本輪實驗。
