# 固定 COCT：二次切分與連續片段查詢實驗

日期：2026-10-27。承接 [COCT主庫比較](coct-comparison.md)。使用者已選擇「詞內任意連續片段」：半導／導體都可找到半導體，股可找到個股；半導不能匹配分散的半年／導師。詞庫須為外部資料，不嵌入引擎。這是隔離實驗，尚未修改產品runtime、索引或既有正規化實作。

可重跑程序、公開合成測資、真實資料來源manifest及B0–B4配置已整理至獨立的 [meilisearch-search-eval](https://github.com/derektu/meilisearch-search-eval)。[獨立repo首輪重跑](https://github.com/derektu/meilisearch-search-eval/tree/main/reports/reference-2026-10-27)與本頁歷史實驗分開保存；後續規模效能及保留集研究在該repo維護，不作#162的結案前置。第三方全文與COCT詞庫未上傳。

## 固定項目與規則

1. COCT版本、新聞詞頻、碰撞加總與零值平滑沿用前輪，詞頻檔SHA256 `4b2d026eaa353ffde900f36049e72f1fa6902fbf25b14dbcb0b675d541e01264`。不逐題補詞、不換字典、不做同義詞／地區用詞替換。
2. 保留第一輪COCT辨識的完整詞作為候選詞界；台積電、伺服器不因內含短詞而必須拆成台積／電、伺服／器。
3. 完整詞查詢需能找到完整詞；片段補充支援詞首、詞中、詞尾及單字，例半導／導體→半導體、金→現金流量。
4. 每個片段須在同一個搜尋欄位中連續出現。半導不能靠半年與導師分散命中；觀光不能靠直觀與賣光拼成。也不跨title／body邊界拼字。
5. 明確多詞維持AND，例台積電 法說、觀光 產業可以在同一文件不同位置出現。COCT已辨識的多詞輸入如觀光產業，維持觀光／產業的AND語意。
6. 未登錄短片段若被切成相鄰單字，不把這些單字分散AND；保留其連續性要求。這包含半導、拆股。具體合併策略需要在實驗中記錄，不能宣稱所有自然語句分詞已解決。
7. 引號片語要求正規化原文連續，例"觀光產業"不得只因觀光與產業分散出現而命中。
8. 在其餘條件相同的對照文件中，完整詞命中排在片段命中前。正式產品跨欄位、詞頻及多詞相關性排序仍需獨立驗證，不能由參考實驗的簡單排序取代。

空白、NFKC、簡轉繁、臺台與原文保留沿用#162。片段索引需能獨立召回，不能只過濾Meili已找到的候選，否則補不回導體→半導體。原文高亮也需保留正規化位置到原文的映射。

「詞內片段」與跨COCT相鄰詞界但原文字面連續的情形，例如離岸／風電內的岸風，先列探索題；不由實驗程式擅自把未確認的詞界偏好當驗收結論。

## 預先凍結的驗收資料

23份文件、22題、38組應命中、468組不得命中，於候選實驗前固定在本票gitignored `coct-query-rules/suite.json`。每題對這23文件完整列出expectedIds／forbiddenIds；另外保留既有34真實文件／60題及原五組正負例。

| 類型 | 查詢／正例 | 必須排除或保留的行為 |
| --- | --- | --- |
| 完整詞 | 觀光、資安、半導體、台積電、拆股、伺服器 | 排除直觀／賣光、安全的資產、半年／導師、台灣累積電力等散字負例 |
| 詞首／詞尾 | 半導／導體→半導體；伺服／服器→伺服器；台積／積電→台積電 | 片段連續；不得分散拼字 |
| 單字 | 股→個股／股票；金→自由現金流量 | 不因完整詞界而遺失詞內字面召回 |
| 多詞 | 台積電 法說；觀光 產業 | 各詞可分散，但各詞自身不可拆字分散 |
| 無空白多詞 | 觀光產業 | COCT辨識出的觀光／產業仍可AND |
| 引號 | "觀光產業" | 排除觀光旅遊帶動地方產業 |
| 正規化 | 观光、臺積電、全形空白 | 與既有正規化結果一致 |
| 排序 | 導體電阻實驗 vs 半導體製程進步 | 同條件下前者完整詞優先 |

跨詞界片段與「買股」先記錄，不列未確認的pass／fail。

## 比較組與驗證層級

- A：外部COCT主庫＋原始二次切分。
- B：相同外部COCT主庫＋保留第一輪詞界。
- C：B＋獨立連續片段索引／查詢驗證的參考實驗。它用來確認召回與排除規則；不等同已完成產品整合，也不能把參考排序當完整Meili排名。

引擎為Mac arm64 Meilisearch 1.53.2，API dictionary固定空白。A/B直接走產品搜尋backend與隔離真實引擎；C記錄候選來源、查詢分組、正規化位置及原文映射。比較完整membership、既定正例、負例排序、索引成本與暖查詢p50／p95。效能只報同機受測資料，不由小資料宣稱大規模可用。

外部詞庫另做載入實驗：同一binary hash，對不同檔案重啟並建立新索引，確認資料可更換而不重新編譯。人工toy詞庫只作載入證明，不混入COCT品質比較。首次載入時機、缺檔／壞檔、是否fallback及重建索引要求需如實記載；下載器、熱更新、正式App啟動驗證不在本輪。

本輪不改產品畫面與正式資料；不跑Web／Desktop安裝驗收。產品整合時，另需更新issue的scenario、搜尋Web流程、runtime重建與受影響平台驗證。

## 實驗結果

| 比較組 | 新suite正例召回 | 誤收負例 | 通過查詢 |
| --- | ---: | ---: | ---: |
| A 外部COCT＋原二次切分 | 32/38 | 3/468 | 14/22 |
| B 外部COCT＋保留第一輪詞界 | 32/38 | 3/468 | 14/22 |
| C B＋連續片段補召回／驗證參考 | 38/38 | 0/468 | 22/22 |

A/B對新suite的命中ID與排序相同。關閉二次切分確實保留台積電、伺服器的第一輪詞界，但單獨這個改動不會補齊片段召回，也不會修好未登錄查詢被拆字的匹配。

兩組失敗題為W01／N01（觀光／观光誤收有空白的觀 光）、F01（半導誤收半年／導師）、F02／F03／F05／F07／C02（導體、導、積電、服器、金漏掉詞內片段）。既有五組完整詞quoted／unquoted案例仍通過，表示更嚴格的新案例確實揭露前輪未測到的問題。

C用獨立Unicode字元位置posting索引產生候選，再驗證各查詢片段於同一欄位的連續字串；不是只過濾B的既有候選。查詢先用固定COCT的第一輪切詞，再將相鄰漢字單字群合成連續片段要求。無漢字查詢直接保留B結果，以避免把英文錯字容忍一併改掉。這個參考程式不做逐題特判、不讀gold來選候選、不補詞。

### 已證明的案例

- 半導／導體找到半導體，半導不再靠半年／導師分散命中。
- 服器找到伺服器，積電找到台積電。
- 金找到自由現金流量；股在個股內的rawStart=1位置確實被索引並命中。A/B的原C01命中來自同文件另一處的股票，不能單靠其文件命中聲稱已支援個股。
- 明確多詞AND、COCT多詞AND、引號連續片語及正規化案例通過。
- 導體完整詞與半導體片段均可召回，該fixture完整詞在前。但排序只保留B已找到的合格結果順序，新增片段候選排在後面；未實作一般性的完整詞／片段分數，不能宣稱所有排序都已解決。
- 三組原文位置映射通過：😀臺積電中的台積電、ＡＩ伺服器中的ai、半导体中的導體，均可對回正確原字串。

### 真實文件回歸與限制

原34文件／60查詢、50組既定正例，A/B/C皆維持49/50；剩下既有台績電錯字漏查。C的五題預期零命中也保持。這只代表既定正例無新增漏查，不是整體precision已完整驗證。

相對B，C增加四題的文件命中，沒有移除命中：股11→12、電11→13、金7→8、利率5→6。補回的文件包括個股、現金流量及其他詞內字面片段；新增文件未有完整相關性標註，不直接計作precision改善。26題無漢字查詢是直接繼承B，不算獨立英文檢索實驗。中英混合錯字與其他Meili查詢語法尚未完整驗證；C對漢字要求連續字面，不能推論中文錯字容忍也完整保留。

岸風／離岸風在C會找到離岸風電。這是跨COCT詞界、但原文連續的情形，目前仍是探索題，不列為已確認的最終產品規則。買股不會因買與股票分散出現而命中。

A/B各180次HTTP暖查詢：A p50/p95為5.47/53.36ms，B為4.70/59.19ms，沒有足夠證據主張關閉二次切分更快。C是記憶體參考，只量posting及驗證處理、未含引擎查詢或HTTP；不能與A/B直接比較，也沒有證明全量索引大小、持久化、更新或大資料效能。

### 外部詞庫載入

同一Meilisearch 1.53.2 arm64二進位SHA256 `012c3025b50b660615cd58ad0358f6f8c42e3d7e1c61d999f95e7f7d9a265cb4`，透過獨立詞庫檔載入COCT。品質比較中詞庫hash固定。另用同一檔案路徑，先放原COCT、再放人工toy詞庫，每次重啟並使用新DB，確認binary hash不變、詞庫hash改變、切詞及搜尋改變；證明換詞庫不需要rebuild引擎。人工toy沒有混入品質結果。

目前載入器仍採LazyLock：首次中文tokenize才讀取；缺檔或解析錯誤會在該時點panic，沒有默默fallback。這是原始碼確認的限制，不能宣稱正式啟動前驗證／友善錯誤已完成。正式整合需要啟動前檢查、明確資料版本與重建索引；本輪沒有實作下載器、熱更新或App設定介面。

### 結論與下一步

外置詞庫路線可行；片段查詢需要獨立補召回與連續性驗證，不能只靠關閉二次切分。C驗證了已確認語意可以同時滿足，但尚不是可交付的完整搜尋backend。正式整合需確定片段索引的儲存／更新、與Meili合併排序、中文及混合查詢錯字容忍、跨詞界片段規則與全量效能。
